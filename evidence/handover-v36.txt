THE SHIPPING CERTIFICATE (the notary notarizes its own landing)
----------------------------------------------------------------
The final `aeos save-proof` (default command) runs after this
receipt is written; its certificate lands in evidence/save-proofs/
whose contents are excluded from the Merkle root BY LAW — the
receipt about the tree is not the tree. Its filename embeds the
root of the exact tree being tagged v36.0.0. Anyone can re-prove
the tag at any time:

  git checkout v36.0.0
  aeos save-proof --verify evidence/save-proofs/save-proof-*-verified.json --against-tree

That command re-hashes the tagged tree and compares it to the
certificate — VERIFIED means the tag you are standing on is the
tree that was proven. Done is a certificate, not a sentence.

HONEST LIMITS (stated plainly)
------------------------------
- The default signature is a sha256 self-digest: tamper-EVIDENT,
  not origin-authentic. AEOS_PROOF_KEY upgrades to HMAC-SHA256
  between key-sharers. Asymmetric signing needs a dependency:
  rejected (ADR-002).
- Certificates carry no timestamps: determinism is law. Time lives
  here, in the receipt, never in the artifact.
- The outbox is at-least-once toward an endpoint, exactly-once
  locally; the consumer dedupes on the idem key we send. That is
  the honest contract; anything stronger would be a lie queues
  cannot keep.

[v36.0.1 ADDENDUM — the cold clone refused, and it was right]
================================================================
The release notes for v36.0.0 promise:
  git checkout v36.0.0 && aeos save-proof --verify ... --against-tree
Executed from a FRESH CLONE (not the warm worktree):

  SAVE-PROOF — REFUSED: the tree no longer matches the certificate

Diagnosis (snapshot diff, warm worktree vs cold clone):
  only in worktree: []
  only in clone:    []
  content differs:  ['src/aeos.egg-info/PKG-INFO',
                     'src/aeos.egg-info/SOURCES.txt']

Root cause: src/aeos.egg-info — build metadata regenerated by every
`pip install -e .`, its content depending on WHEN pip ran — was
inside the Merkle root. The warm worktree hid it; the fresh clone
refused it. This is the v35.1 lesson in a new costume: validate
from the cold environment, because the warm one flatters you.

Fix (v36.0.1): *.egg-info / *.dist-info / *.egg directories and
.DS_Store join the exclusion law — derived trees never count toward
identity. Regression test: test_build_metadata_never_counts
(warm-tree egg-info with different content must not move the root).

Discipline upgrade for this patch: the tag promise was re-proven
from a simulated cold checkout (git archive of the tag + pip
install -e + --verify --against-tree) BEFORE the release was
published — the claim follows the proof this time, not the other
way around.

The v36.0.0 certificate remains in the ledger, unchanged: it
truthfully describes the tree state it hashed (egg-info included).
Certificates are history; the root definition is law; the law was
corrected and the correction is this record.
