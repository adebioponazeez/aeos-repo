WHAT SHIPPED (ADR-051)
================================================================
1. HOOKS AS A FIRST-CLASS SURFACE (Cole Medin, compiled):
   - closed vocabulary of named points on the harness scaffold:
     task.pre/post, wave.pre/post, subplan.pre, refusal
   - ordered, thread-safe, inspectable registrations
     (`aeos hooks`; `--register-demo` runs a live veto)
   - pre-hooks VETO (HookVeto: the message IS the reason, plain
     language, never a traceback) or REDIRECT (rewrite the action
     class WRITE->READ: intent preserved, danger removed)
   - observers can never crash the run they observe (errors
     collected + named)
   - decoupled from the agent: the bus emits from orchestrator
     seams; the kernel logic never moved (ADR-002)
2. RECURSIVE HARNESS GRAPHS (Recursive Agent Harness pattern,
   arXiv:2606.13643 — "the recursive unit is a full harness, not
   a model call"):
   - TaskSpec.subplan: a task with a subplan expands into a
     NESTED Orchestrator — its own waves, governor decisions,
     gates, and depth-stamped events (subplan.start/end)
   - a recursive STATE MACHINE in the honest sense: a state that
     expands into a sub-state-machine, bounded and observed
   - MAX_SUBPLAN_DEPTH = 3: deeper refuses NAMED — "recursion is
     a tool, not a trap" — and the refusal flows to the refusal
     hooks like every refusal
   - child failure fails the parent NAMED ("subplan unresolved")
   - hooks compose through every level of nesting
Live demo receipt (aeos hooks --register-demo):
     safe task   -> SUCCEEDED
     destructive -> ESCALATED (vetoed NAMED by the hook)

Honest scope (ADR-051): hooks are in-process callables inside the
OS trust boundary — guardrails against agent behavior, not a
plugin sandbox against hostile code. Subplans are runtime
constructs; durable checkpoints store the parent's settled state
and the child re-derives (idempotent handlers, spec §14).
